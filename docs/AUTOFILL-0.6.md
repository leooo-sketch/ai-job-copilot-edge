# 职舟 0.6.0：减少网申手填

## 升级时保留已有资料

1. 在当前有资料的插件中，打开“维护资料库”，先点“导出 JSON”保存本地备份。备份包含个人信息，不要上传公开仓库。
2. 在 Edge 扩展管理页找到当前使用的职舟，核对扩展 ID 和已加载的文件夹。不要先卸载，也不要把新版作为另一个插件加载。
3. 将新版压缩包解压到临时文件夹，再把包内文件复制覆盖到原来加载的插件文件夹（manifest.json 所在目录）。不要删除浏览器用户数据。
4. 在原插件卡片上点“重新加载”，确认版本为 0.6.0、扩展 ID 未变。关闭再打开侧栏，并刷新招聘页面，避免旧内容脚本继续运行。
5. 检查资料库里的教育、工作、项目等内容仍在，再重新扫描表单。若必须换目录或 ID，先导入第 1 步的 JSON，核对完成后再考虑移除旧插件。

本版继续使用 candidateAutofillProfile 存储键和 schemaVersion 3，不清空简历、资料库或模型配置。新增的对应关系只保存于本机 autofillFieldMappings；最多 300 条，记录字段路径而非复制个人信息。没有内置任何个人 API key。

## 本次改进

- “必填项未填写”等校验提示不再参与字段标题识别。
- 分开的开始年/月、结束年/月按同一条经历取值。支持已有公司/学校名称对齐，避免网页顺序不同造成串填；扁平布局中公司名称之前的日期也归入本条记录。
- “工作职责”“职位名称”补充精确匹配；旧资料只有经历概述时，提供同条概述作为待确认建议，不生成虚构职责。
- 增加获奖时间、证书日期、毕业届次、最高学历学习形式的匹配；奖项、证书按条目分别编辑。
- 下拉选择按可见文字匹配，不把内部编码当成月份；限制候选弹层范围，填写后回读验证。文本被网页回退会报告失败，而非只看执行过点击。
- 无法自动判断时，展开字段卡片中的“从资料库选择内容 / 修正对应关系”。选择已有内容、检查预览，再点填写。普通字段在同网站同路径记住对应关系；重复经历不记固定数组下标。可以选择“恢复自动识别”清除记忆。
- 千问辅助判断继续只能返回资料路径，不能发明值；高置信度本地映射不被模型覆盖。工作经历用于实习栏目仍需人工确认，敏感信息仍不默认勾选。

## 同类实现研究

查阅日期：2026-09-05。学习机制、独立实现，未整包复制第三方代码，也未依据 stars 宣称可靠性。

- [FormPilot](https://github.com/rockbenben/form-pilot)：平台适配、启发式识别、页面/字段记忆的分层思路。本版借鉴“规则识别 + 人工纠正记忆”，不直接采用其 Moka 点击逻辑；额外加入可见值匹配和回读验证。
- [FormPilot Moka adapter source](https://github.com/rockbenben/form-pilot/blob/main/lib/engine/adapters/moka.ts)：参考 Moka 常见字段与下拉控件结构；本版加入 React Select 等结构，但不能据此保证所有 Moka 客户页面一致。
- [Simplify 官方使用说明](https://help.simplify.jobs/articles/2415391-using-copilot-to-autofill-applications)：复用重复问题答案和资料复制兜底。本版采用本地字段对应关系与资料选择器，不复制其私有实现。
- [JobApplyAutofill](https://github.com/aaa-wxl/JobApplyAutofill)：参考本地规则、AI 路径匹配及人工复核的组合方式。

## 验证与边界

运行 npm run check：包含 30 项测试和全部扩展 JavaScript 语法检查。新增测试使用 jsdom 与虚构资料，覆盖 Moka 风格校验提示、倒序经历、扁平布局、分离日期、自定义下拉、文本回退、千问路径约束、人工映射和旧资料编辑往返。

尚未完成用户当前真实 Moka 页面端到端复测：连接现有浏览器标签超时。本次没有修改或提交真实招聘表单，没有操作已安装扩展或浏览器存储，也没有实际调用个人 API key。

省市区级联、特殊日历、跨域 iframe、虚拟列表未加载选项，以及网站新增/改版控件仍可能需要手动选择或后续适配。资料缺失时不会猜测籍贯、行业、证书或奖项。测试通过不等于所有招聘网站 100% 自动填写。
